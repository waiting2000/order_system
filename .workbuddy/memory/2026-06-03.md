## 多外网访问部署 + 系统优化（1、2、3）

### 外网访问方案讨论
- 用户部署到云服务器后询问如何让外网访问
- 推荐方案：CloudFlare Tunnel（免费、零改动、无需公网IP）
- 备选：云服务器部署、frp、ngrok

- 建议：SSH方式clone 或 本地打包scp上传

### 系统优化（优先级1、2、3）

#### 1. 每日自动清空机制
- **后端**：`GET /orders` 增加 `WHERE date(d.created_at) = date('now', 'localtime')` 过滤
- 今天之前的订单自动不返回，实现"每日重置"效果

#### 2. 多人点同一道菜
- **后端**：去掉全局去重，改为「同一人 + 同一菜 + 今天」去重
  - 原逻辑：`WHERE recipe_id = ?`（任何人点过都不能再点）
  - 新逻辑：`WHERE recipe_id = ? AND nickname = ? AND date(created_at) = date('now', 'localtime')`
- **前端 MenuContext**：
  - `todayOrders` 允许多条相同 `recipe_id` 的记录
  - `toggleTodayMenu` 改为按 `nickname` 查找「我的订单」来取消
  - `isInTodayMenu` 改为检查「我」是否点了这道菜
  - `todayRecipes`（聚合数据）按 `recipe_id` 分组，每个菜显示 `_nicknames` 数组
- **前端 TodayMenu**：
  - 显示每个菜的多个点菜人标签（当前用户高亮）
  - 只有点过这道菜的人才能看到取消按钮
  - 汇总显示 `N道 · M人次`

#### 3. MenuBrowser 搜索功能
- 顶部添加搜索框（带搜索图标和清除按钮）
- 支持按菜名和描述模糊搜索
- 搜索无结果时显示对应提示 + 清除搜索按钮
- 搜索状态下分类标签仍然可用（先分类后搜索）

### 构建验证
- `npm run build` 成功，36个模块，628ms完成

## 技术决策
- 每日清空用「查询时过滤日期」而非「定时删除」，更简单且无副作用
- 多人同菜场景：数据库保留多行，前端按菜聚合展示
- 搜索用前端过滤（数据量小），未改后端API（虽然后端已支持search参数）
