## 错误提示优化 — Toast 全局通知系统

### 新增文件
- **src/context/ToastContext.jsx**: ToastProvider + useToast hook
  - `toast.error(msg)` — 红色，5秒自动消失
  - `toast.success(msg)` — 绿色，3秒自动消失
  - `toast.info(msg)` — 蓝色，3秒自动消失
  - 右上角堆叠显示，最多5条，滑入动画
  - 每条可手动关闭

### App.jsx
- 在 AuthProvider 和 AuthGate 之间插入 `<ToastProvider>`

### MenuContext.jsx 全部 API 调用接入 Toast
- `fetchData()`: 网络错误 → toast.error('加载数据失败，请检查网络连接')
- `addRecipe()`: 成功 → toast.success('「菜名」已添加')；失败 → toast.error + throw
- `updateRecipe()`: 成功 → toast.success('「菜名」已更新')；失败 → toast.error + throw
- `deleteRecipe()`: 成功 → toast.success('「菜名」已删除')；失败 → toast.error + throw
- `toggleTodayMenu()`: 409冲突 → toast.info('你已经点过这道菜了')；失败 → toast.error
- `clearTodayMenu()`: 成功 → toast.success('今日菜单已清空')；失败 → toast.error
- `importData()`: 成功导入 → toast.success('成功导入 N 道菜谱')；全重复 → toast.info

### RecipeManager.jsx 异步错误修复
- `handleSave()`: 改为 async + try/catch，错误时**保持表单打开**（之前无论成败都关闭）
- `handleDelete()`: 改为 async + try/catch，错误时**保持确认弹窗**（之前无论成败都关闭）

### 设计决策
- Toast 放在 MenuContext 内部（而非每个页面各自调用），好处：一处改动覆盖所有操作
- Context 方法 throw 让调用方可自行拦截（如 RecipeManager 保持表单打开）
- 成功操作也有提示（而不只是错误），给用户明确的正反馈
