### 系统优化（优先级1、2、3）

#### 1. 每日自动清空机制
- **后端**：`GET /orders` 增加 `WHERE date(d.created_at) = date('now', 'localtime')` 过滤
- 今天之前的订单自动不返回，实现"每日重置"效果

#### 2. 多人点同一道菜
- **后端**：去掉全局去重，改为「同一人 + 同一菜 + 今天」去重
  - 原逻辑：`WHERE recipe_id = ?`（任何人点过都不能再点）
  - 新逻辑：`WHERE recipe_id = ? AND nickname = ? AND date(created_at) = date('now', 'localtime')`
- **前端 MenuContext**：
  - `todayOrders` 允许多条相同 `recipe_id` 的记录
  - `toggleTodayMenu` 改为按 `nickname` 查找「我的订单」来取消
  - `isInTodayMenu` 改为检查「我」是否点了这道菜
  - `todayRecipes`（聚合数据）按 `recipe_id` 分组，每个菜显示 `_nicknames` 数组
- **前端 TodayMenu**：
  - 显示每个菜的多个点菜人标签（当前用户高亮）
  - 只有点过这道菜的人才能看到取消按钮
  - 汇总显示 `N道 · M人次`

#### 3. MenuBrowser 搜索功能
- 顶部添加搜索框（带搜索图标和清除按钮）
- 支持按菜名和描述模糊搜索
- 搜索无结果时显示对应提示 + 清除搜索按钮
- 搜索状态下分类标签仍然可用（先分类后搜索）

## 技术决策
- 每日清空用「查询时过滤日期」而非「定时删除」，更简单且无副作用
- 多人同菜场景：数据库保留多行，前端按菜聚合展示
- 搜索用前端过滤（数据量小），未改后端API（虽然后端已支持search参数）

## 登录功能（个人账号模式）

### 后端
- **server/db.js**: 新增 `users` 表（id, username UNIQUE, password_hash, nickname）
- **server/middleware/auth.js**: JWT 认证中间件 + token 生成（30天过期）
- **server/routes/auth.js**: 
  - POST `/api/auth/register` - 注册（bcrypt 加密）
  - POST `/api/auth/login` - 登录
  - GET `/api/auth/me` - 获取当前用户
- **server/routes/api.js**: 所有业务路由加 `authMiddleware` 保护
- **server/index.js**: 挂载 `/api/auth`（免认证）和 `/api`（认证后）
- **POST /orders**: 昵称不再从请求体取，改为 `req.user.nickname`

### 前端
- **src/context/AuthContext.jsx**: AuthProvider，token 存 localStorage/sessionStorage
- **src/context/MenuContext.jsx**: 
  - 从 AuthContext 获取 token 和 user
  - 所有 fetch 请求加 `Authorization: Bearer` header
  - 移除本地 nickname 管理（昵称来自登录用户）
- **src/pages/Login.jsx**: 登录/注册页面，支持切换模式、"记住我"
- **src/App.jsx**: 
  - AuthGate 组件：未登录 → Login 页
  - 移除 NicknameModal（昵称由注册时设置）
  - 顶部显示当前用户昵称 + 退出按钮

### 依赖
- bcryptjs: 密码哈希
- jsonwebtoken: JWT 生成与验证

### 安全说明
- 默认 JWT_SECRET = 'family-menu-secret-change-in-production'
- 生产环境应设置为环境变量 `JWT_SECRET`
- 密码最少 4 字符，bcrypt salt 10 轮
- Token 过期 30 天
